❓ 为什么要换？CFW 已经停更很久了

如果你还在用 Clash for Windows (CFW)，应该已经注意到它的 GitHub 仓库很久没有实质性的代码更新了，连安全补丁都没有。CFW 的内核停留在旧版 Clash，而社区早已转向了 Mihomo（Clash Meta） 内核。这意味着你没法用新的协议（比如 Hysteria2、VLESS），也享受不到 Fake‑IP 模式的诸多改进。再加上偶尔出现的 DNS 泄漏、老旧 Chromium 带来的内存问题，继续坚持真的没太大必要。

Clash Verge Rev 是目前社区里接替 CFW 的主流选择，基于 Tauri 框架 构建，轻量、更新频繁，并且完美兼容你以前的配置文件格式。接下来我会带你一步步把 CFW 的东西搬到 Rev 上，整个过程大概十分钟，主要时间花在核对规则和调整一些默认行为上。

📦 迁移前的准备：备份与清理

先别急着卸载 CFW。打开 CFW 的配置目录，默认在 %USERPROFILE%\.config\clash 或者 CFW 程序目录下的 profiles 文件夹。里面有你的所有配置文件（config.yaml 或 xxx.yaml）、订阅缓存、以及一些临时文件。把整个 profiles 文件夹复制到桌面备用。同时，记下你在 CFW 里常用的端口设置：HTTP 代理端口（默认 7890）、SOCKS5 端口（默认 7891）、以及 TUN 模式是否开启。

CFW 的“General”选项卡里还有一些设置，比如系统代理类型、是否允许局域网连接、日志级别等。最好截个图，等下在 Rev 里对应着配置，免得忘了原来是怎么设置的。如果你之前还手动改过 config.yaml 里的 dns 或 tun 相关参数，也一起记下来，因为 Rev 对这些字段有更严格的校验，马上会说到。

💡 建议： 不要急着删除 CFW，先保留一段时间作为对比。等确认 Rev 一切工作正常，再彻底卸载。卸载前记得关闭 CFW 的系统代理和开机启动，避免两个客户端同时抢端口。

📋 配置文件的无痛搬运

好消息是，CFW 的配置文件几乎可以直接在 Rev 中使用。你可以在 Rev 的“配置”页面点击“新建” → “从文件导入”，选择你刚才备份的 .yaml 文件。或者直接把文件复制到 Rev 的配置目录（通常是 %APPDATA%\clash-verge-rev\configs 或 ~/.config/clash-verge-rev/configs）。如果你用的是便携版，配置目录就在程序文件夹下。

不过这里有个小坑需要注意。CFW 允许一些“宽松”的 YAML 写法，比如缩进不一致、多余的注释、甚至 proxies 字段为空。但 Mihomo 内核对这些格式比较严格，导入时如果报错，先检查缩进，确保所有字段都是两个空格。还有一个常见问题是 rule-providers 语法：CFW 时代很多人没用过这个功能，如果你的配置里意外带了不规范的 rule-provider 定义，直接删掉就好，后续可以参照 Rule Provider 实战 重新配置。

导入成功后，在 Rev 的配置列表里点击刚才导入的文件，它会自动开始解析节点和规则。你会发现在节点列表里看到和 CFW 一模一样的代理信息。如果节点没显示出来，多半是配置文件的 proxy-groups 和 proxies 字段有拼写错误，可以看看 配置教程 里的完整对照表。

🔄 订阅与规则组的变化

CFW 的用户有很多人用的是机场订阅链接，直接从 URL 拉取配置。在 Rev 里，订阅管理被放到了更显眼的位置：“配置” → “新建” → “从 URL 导入”。粘贴你的 Clash 订阅链接后，Rev 会自动拉取并解析，同时你可以在“更新间隔”里设置自动更新的频率（比如 1440 分钟 = 每天）。这点比 CFW 的“Profile”管理要舒服一些，因为 Rev 把订阅和本地配置分得很清楚，你可以在一个界面里同时管理多个订阅和本地文件，随时切换。更多细节可以翻阅 导入订阅指南。

规则方面，如果你之前在 CFW 里用的是内联规则（直接写在 rules 段），那么迁移过来几乎不用改动。但如果你用了 CFW 不支持的 RULE-SET 或者打算开始使用规则集，Rev 是原生支持的。建议趁这次迁移，把那些冗长的域名列表单独抽成规则集，主配置文件会变得非常干净。操作方式在 Rule Provider 文章 里有完整示范。

🔀 TUN 模式与 DNS 设置的差异

CFW 的 TUN 模式需要单独安装驱动（Wintun），有时候还会和杀毒软件冲突。Rev 在这方面进步很大，TUN 堆栈支持 System、gVisor 和 WFP 三种模式，Windows 下推荐直接用 WFP，不需要安装任何驱动，兼容性也最好。如果你对 WFP 原理感兴趣，可以看那篇 Windows WFP 文章。迁移过来后，你可以在“设置” → “TUN 模式”里直接开启，不用再单独下载任何东西。

DNS 部分需要特别注意。CFW 默认的 DNS 模式是“redir‑host”，而 Rev 强烈推荐使用 Fake‑IP。如果你直接导入 CFW 的配置，里面的 dns 段可能仍然保留了 enhanced-mode: redir-host。建议把它改成 fake-ip，并补上 fake-ip-range: 198.18.0.1/16 和 fake-ip-filter。这能杜绝 DNS 泄漏，体验上的区别可以参考 DNS 配置指南 和 Fake‑IP 深度解析。

一个很具体的小细节：CFW 的 dns 字段里 nameserver 通常写成 114.114.114.114 或 223.5.5.5，这在国内没问题，但在 Fake‑IP 模式下，建议换成 DoH 地址，比如 https://doh.pub/dns-query。因为 Fake‑IP 模式会把所有 DNS 查询都通过代理发出去，如果上游 DNS 是明文的，你的运营商还是会知道你在解析什么域名。

🖱️ 界面和操作习惯的适应

CFW 的用户可能习惯了那个经典的深色界面和侧边栏布局。Rev 的界面相比之下更现代一些，但核心逻辑是相通的。左侧导航从“General”、“Proxies”、“Profiles”变成了“代理”、“配置”、“日志”、“连接”、“DNS”等。节点切换在“代理”页面，和 CFW 的“Proxies”几乎一样，支持点击切换、策略组、延迟测试。

一个容易被忽略的小功能：Rev 的“连接”面板是 CFW 没有的（需要 v2.5.2 或更新版，参看 v2.5.2 新特性）。它可以实时显示每条连接的流量信息、命中了哪条规则、用了哪个节点。这个在调试规则是否生效时非常有用，强烈建议迁移后先点开看看，确认你访问的网站是不是真的走了预期的代理。

托盘菜单也稍有不同。CFW 的右键菜单里可以直接切换代理模式、打开文件夹；Rev 把这些选项放在了“设置”或“托盘图标右键”里，熟悉一下就好。还有，Rev 的开机启动在“设置”里可以独立开启，和 CFW 一样。

⚠️ 迁移后容易踩的五个坑

迁移过程中，我在自己和朋友们的电脑上遇到过下面这些典型问题，提前知道能省不少时间：

问题现象原因解决办法
导入配置后没有节点配置文件里 proxies 字段为空，或缩进错误导致 Mihomo 解析失败检查 YAML 缩进，确保每个 proxies 项以 - name: 开头且缩进正确
开启 TUN 后断网CFW 遗留的 Wintun 驱动与 Rev 的 WFP 冲突先卸载 CFW 的 TUN 驱动：设备管理器 → 网络适配器 → 卸载 Wintun；然后在 Rev 中重新开启 TUN
部分网站走了直连但规则里写了代理CFW 的规则排列顺序和 GEOIP 优先级不同在 Rev 的规则列表里，把自定义规则放在 GEOIP 前面，或使用连接面板排查命中情况
局域网设备无法共享代理CFW 的“Allow LAN”选项在 Rev 里叫“允许局域网连接”，默认关闭在 Rev 设置中开启“允许局域网连接”，并确保防火墙放行 7890 端口
CFW 的旧脚本（如 PAC 文件）不工作CFW 生成的 PAC 文件依赖于 CFW 的进程名放弃 PAC，改用 TUN 模式或系统代理，或者在 Rev 的配置中自定义规则

上面这些坑大多是因为新内核对格式更严格，或者一些历史遗留的驱动冲突。遇到问题时，先看看 常见问题 页面，很可能已经有了现成的答案。

✅ 最后的检查清单

迁移完成后，按下面这个清单逐项确认一下：

  1. ✅ 代理节点能正常测速，延迟显示正常。
  2. ✅ 浏览器能访问 Google、YouTube 等网站。
  3. ✅ 打开 ipleak.net，检查 DNS 和 WebRTC 没有泄漏（DNS 应显示你配置的加密服务器 IP）。
  4. ✅ TUN 模式开启后，命令行 ping google.com 能通（Fake‑IP 下会返回 198.18.x.x）。
  5. ✅ 系统重启后，Rev 能自动启动并恢复代理（如果设置了开机自启）。
  6. ✅ 局域网共享（如果需要）能正常工作，手机连上本机代理后可以上外网。

等这些都没问题了，就可以卸载 CFW 了。卸载前记得在 CFW 里关闭系统代理和开机启动，然后从控制面板正常卸载。如果之前装过 Wintun 驱动，可以顺带在设备管理器里删除。

迁移其实比想象中简单，多数人的配置可以无缝过渡。花点时间把规则集和 Fake‑IP 理顺，后面的体验会比 CFW 时代强很多。如果你还发现了其他迁移过程中的奇葩问题，欢迎到 GitHub Wiki 交流，也许能帮到下一个迁移的人。
