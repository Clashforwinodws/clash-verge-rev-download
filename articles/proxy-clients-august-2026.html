🗓️ 先说说整体印象

每年八月我都有个习惯：坐下来翻一遍自己常用的代理客户端，看看它们这半年来变成了什么样子。今年尤其有趣，因为 Clash for Windows 彻底成为历史，Clash Verge Rev 接过了桌面端的大旗，而移动端、Linux 端也冒出了不少新东西。整个生态不再像前几年那样疯狂涌现新工具，而是进入了一种“沉淀期”——大家不再比拼谁支持的协议多，更多是在打磨稳定性、界面体验和跨平台一致性。

这其实是好事。代理客户端说到底是个工具，不是玩具。用户想要的不过是开机自启、规则生效、不漏 DNS、不断流。谁能在这些基础体验上做得更好，谁就能留住用户。下面我会逐个聊几个目前有代表性的客户端，内容完全基于我自己的实际使用和这段时间的观察，没有任何商业关系。如果你想了解这些客户端背后的内核，可以先去翻一翻 Mihomo 内核解析，很多客户端都是基于它的。

🦀 Clash Verge Rev：稳中求进，细节不断打磨

从 Clash for Windows 迁移到 Clash Verge Rev 的用户越来越多，这在 迁移指南 发布后的下载量上能看出来。Verge 这个月的更新频率虽然没有年初那么密集，但每一次提交都在解决实际问题：对 WFP 模式的进一步兼容、对多显示器 DPI 的修复、TUN 模式下 UDP 缓存的优化等等。这些改动不像“支持新协议”那么吸引眼球，可对于日常需要稳定网络的人来说，远比一个花哨的新功能重要。

有一个我自己注意到的小细节：Verge 的连接面板在 v2.5.3 里增加了按进程名称过滤的功能。以前只能看域名，现在可以直接过滤出 firefox.exe 或 java.exe 的连接，对那些喜欢用规则按进程分流的用户（比如 Rule 模式 里的 PROCESS-NAME）简直太实用了。这个功能是社区 contributor 提交的 PR，也侧面说明 Verge 的开源协作模式正在良性运转。

不过，我在 Linux 上用 Verge 时，偶尔还是会遇到托盘图标不响应的问题，特别是在 KDE 环境里。虽然不影响代理本身，但对强迫症来说总想点两下。官方 Issue 里有讨论，看起来跟 Tauri 框架 的 Linux 托盘实现有关，短期内可能不会完全解决。好在命令行启动和日志一切正常，当网关跑的时候基本不用管界面。如果你也需要在 Linux 上部署，可以看 Linux 安装指南 和 Ubuntu 部署教程。

🍎 Stash：苹果生态里的隐形冠军

Stash 在 iOS 和 macOS 上的体验依然独一档。上个月更新的版本支持了 iOS 18 的自动化捷径深度集成，你可以根据地理位置、时间、Wi-Fi 名称自动切换代理模式。比如我设定的是“离开家自动开启 TUN，连上家里的 Wi-Fi 自动关闭”，用了两个月，几乎没出过错。这种自动化是 Android 和桌面端目前很难匹敌的。

但 Stash 的收费策略最近在社区里有些讨论。iOS 版付费没问题，但 macOS 版需要单独再买一次，让一些同时用 iPhone 和 Mac 的用户觉得成本偏高。而且它是闭源的，虽然核心基于 Mihomo，但上层代码无法审查。如果你特别在意软件自由，可能会更倾向于在 Mac 上用 Clash Verge Rev。我自己的做法是移动端用 Stash，桌面端用 Verge，配置文件通过 Git 同步，两者互补。如果你还没决定，可以看看之前写的 Stash 与 Verge 对比。

🌐 Hiddify：伊朗团队的开源力量，用面板整合一切

Hiddify 这个名字在国内可能不如 Clash 响亮，但它在国际社区的影响力正在迅速扩大。它是一个“面板+客户端”的整体方案：服务端可以一键部署 Xray、Hysteria2、TUIC 等协议，客户端则覆盖了 Android、iOS、Windows、macOS、Linux。这种全家桶模式有点像当年的 V2Ray + V2RayX，但做得更现代。

Hiddify 客户端同样基于 Mihomo 内核（它们叫“Clash Meta”），但上层 UI 是用 Flutter 写的，界面风格非常统一。我试过它的 Windows 版，感觉交互逻辑跟 Verge 不太一样：它更强调“Profile”的概念，一个 Profile 对应一个完整的代理订阅+规则+DNS 配置，切换 Profile 就等于切换一整套网络环境。对于需要同时管理多个工作场景（比如公司、家庭、出差）的用户来说，这个设计比 Verge 的单一配置列表更直观。但在自定义规则的灵活性上，Verge 还是更胜一筹，因为 Hiddify 目前对 Rule Provider 的支持比较初步。

从 GitHub 的 star 数来看，Hiddify 的增长曲线很陡峭，社区贡献者以伊朗和俄罗斯开发者为主。考虑到这两个地区的网络环境，他们对于抗封锁协议和混淆技术的研究非常深入，这也是为什么 Hiddify 在 Reality 协议和 IPv6 隧道方面做得很超前。如果你喜欢折腾服务端，可以关注一下它。

🌸 Flower 与新秀：Mihomo 内核下的百花齐放

Flower 是最近几个月才冒出来的一个 macOS 专用客户端，界面设计非常极简，类似于原生的 Mac 应用风格，没有侧边栏，所有操作都在一个窗口内完成。它也是基于 Mihomo 内核，但只支持 macOS，定位明显是冲着喜欢原生体验的 Apple 用户去的。目前功能还比较简单，不支持 TUN 模式（只能系统代理），规则编辑也没有可视化界面，需要手动改配置文件。但它的 UI 确实漂亮，如果后续加入更多功能，可能会吸引一部分 Stash Mac 版的用户。

除此之外，还有几个基于 Mihomo 的 Web 面板客户端（比如 Metacubexd、Yacd），它们不是独立应用，而是运行在浏览器里的管理界面，通过 API 控制后端的 Mihomo 内核。这种架构特别适合软路由或 VPS 场景——你在服务器上跑一个 Mihomo 内核，然后通过网页管理配置，不用装任何 GUI。我在家里的软路由上就是这么干的，配合 TUN 模式 实现全屋透明代理。

📡 协议层面：Hysteria2 普及，Shadowsocks 2022 增量

协议这块，Hysteria2 在 2026 年已经成为机场和自建节点的标配之一。它的抗丢包能力和 0-RTT 握手让很多原来用 VMess 的用户转向了它。Clash Verge Rev 从 v2.5.2 开始完整支持 Hysteria2，配置也非常简单，就是填一个 hysteria2 类型的节点。

另一个值得关注的趋势是 Shadowsocks 2022 的普及。这个新版本修复了原来 AEAD 套件的一些安全缺陷，使用更强的加密和抗重放机制。我在 Shadowsocks 协议解析 里详细写过它的原理。目前支持 SS 2022 的节点还不多，但主要客户端都已经适配了。如果你在自建节点，可以考虑升级到 2022 版本，安全性有质的提升。

另外，VLESS + Reality 的组合仍然是最强的伪装方案之一，尤其是在移动端。Stash 和 Hiddify 都支持 Reality，Clash Verge Rev 则需要通过 Mihomo 内核的 vless 类型节点来实现。配置时需要注意 flow: xtls-rprx-vision 和 servername 的正确填写，否则会握手失败。

📱 移动端：iOS 依然需要自签，Android 选项变多

iOS 用户的不便依然存在：除了 Stash（付费）和 Shadowrocket（付费），其他开源客户端基本都需要自签或者 TestFlight。对于不想付费的人来说，每隔几天就要重新签一次 IPA 仍然很麻烦。虽然有 AltStore、SideStore 这些工具，但门槛还是高。

Android 这边就好多了。除了 Clash Meta for Android（CMFA）这个老牌客户端，还出现了几个基于 Mihomo 的新 App，界面更现代，支持 Material You 动态颜色。最重要的是，它们全部开源免费。如果你在 Android 上用代理，不妨试试这些新选择，有些在耗电控制和后台保活上比 CMFA 做得更好。

👥 社区与生态：GitHub 的活跃度是一面镜子

看一个开源项目的生命力，GitHub 的 Issue 和 PR 活跃度是最直接的指标。Clash Verge Rev 的仓库目前几乎每天都有新的 Issue，大部分是使用问题，但经常能看到社区成员帮忙回复。Mihomo 内核的仓库则更偏技术讨论，比如 QUIC 协议栈的优化、内存分配器的选择等。如果你对底层开发感兴趣，插件开发指南 是一个不错的起点。

Stash 因为是闭源，没有公开的 Issue 追踪，只能通过邮件反馈。Hiddify 的社区则更国际化，Issues 里英语、俄语、波斯语混杂，非常有特色。

有一个趋势值得注意：越来越多的新手用户直接跳过 CLI 工具，从机场订阅直接跳到图形化客户端。他们不关心 YAML 怎么写，只想点几下按钮就能上网。这对客户端的设计提出了新的要求——如何在不暴露底层复杂性的同时，让用户能掌控核心设置。这也是为什么 YAML 为什么还没被淘汰 这个话题会引发那么多讨论，因为图形界面的背后仍然是那一行行配置。

✅ 我自己的选择与推荐

八月快过半，总结一下我目前的配置：主力桌面（Windows + Linux）用 Clash Verge Rev，移动端用 Stash，软路由上跑 Mihomo 内核 + Metacubexd Web 面板。Hiddify 我会继续观察，它的面板服务端对于需要自建机场的人来说很有吸引力。Flower 等新秀我会保持关注，但目前它们的功能深度还不足以替代成熟客户端。

如果你想从零开始搭建一整套代理环境，我的建议是：先选一个稳定的客户端（桌面推荐 Clash Verge Rev，移动端推荐 Stash），然后花时间把 配置 和 规则 弄明白。工具会变，但网络原理和配置思路是相通的。希望这篇观察能给你一些有用的参考，也欢迎到 Wiki 或者 常见问题 页面交流你的使用心得。
