📱 从 Clash for Android 换过来的第一周

我用过的 Android 代理客户端不算少，从最早的 Shadowsocks 到后来的 V2RayNG、Clash for Android，再到现在的 FlClash。说实话，Clash for Android 停更之后，我试了四五个替代品，最后留下的是 FlClash——不是因为它的 UI 多花哨，而是它在一些细节上比别的客户端更知道“用户真正需要什么”。但这些东西往往藏在菜单很深的角落里，不翻几次根本发现不了。我大概用了一个多星期才把这些功能全部摸清，有些还是从 GitHub Issue 里看到别人提到才注意到。

这篇文章就是来分享这些容易被忽略的功能。FlClash 和 Clash Verge Rev 的内核同出一脉（都是 Mihomo），所以很多思路和桌面端是相通的。如果你在桌面端用 Verge，手机端用 FlClash，配置文件和规则几乎可以通用，这种一致性让我省了很多心思。关于两者搭配使用的思路，我之前在 Stash 与 Verge 对比 那篇里也提到过。

🔀 WiFi 与移动数据自动切换配置

这是我目前最常用的功能之一，也是很多人不知道的。FlClash 支持根据当前网络环境自动切换配置文件。比如我在家连的是自己的 WiFi，宽带本身能直连一些国外网站，这时候可以让 FlClash 切换到一套“直连为主”的配置；而出门用移动数据时，自动切回“全局代理”的配置。

设置位置在“配置”页面 → 长按某个配置文件 → 选择“关联网络”。你可以为每个 WiFi 网络和移动数据单独指定不同的配置文件。这样的话，你完全不需要手动切换——回到家连上 WiFi，FlClash 自动帮你换好；出门断开 WiFi，又自动切回来。这个功能在官方文档里只有一小段描述，很多人根本没注意到。但它对于家里有软路由、公司有专线的用户来说，简直是救星。

一个小细节：切换配置时，FlClash 会有一个短暂的网络中断，大约 2-3 秒。如果你正在打电话或者视频会议，建议不要在配置切换的瞬间依赖网络。不过日常刷网页、看视频几乎感知不到。

💡 进阶： 如果你想让移动数据也区分“5G 和 4G 不同配置”，目前 FlClash 还不支持这么细。但它支持“漫游状态”的单独匹配，对于经常出国的用户，可以给漫游状态指定一个低延迟节点配置。

🎯 按应用代理：让某些应用直连，其他走代理

在 Android 上，Clash 客户端的 VPN 模式一般会接管所有应用的流量。但你可能不想让某个应用走代理，比如银行类 App 走代理反而容易触发风控，或者国内视频 App 走代理反而更卡。FlClash 很贴心地提供了一个“应用分流”功能，可以精确控制每个应用是否走代理。

在“设置” → “应用分流”里，你可以看到一个应用列表，每个应用后面有三个选项：代理、直连、跟随全局。默认所有应用都是“跟随全局”，你可以把银行、支付宝、微信这些应用单独设为“直连”，让它们完全绕过代理。这个功能在 Clash Verge Rev 桌面端对应的是 PROCESS-NAME 规则，但 FlClash 把它做成了可视化界面，方便多了。如果你在桌面端也想要类似效果，可以看 Rule 模式详解 里的 PROCESS-NAME 用法。

还有一个小技巧：对于某些需要“部分走代理、部分直连”的应用（比如浏览器访问国外网站走代理，访问国内网站直连），不要用应用分流把它设成直连，因为这样它所有流量都直连了。正确做法是保持“跟随全局”，然后在规则里做精细化的域名分流。

📡 局域网共享代理：手机变随身网关

当你在酒店或者朋友家，没有路由器翻墙，但有其他设备（比如 Switch、电视盒子、笔记本电脑）需要走代理，FlClash 可以帮你把手机变成一个小小的代理网关。开启“局域网共享”后，FlClash 会在手机上监听一个端口（默认 HTTP 7890、SOCKS 7891），局域网内的其他设备把代理地址设成手机的 IP 就可以上网了。

设置位置在“设置” → “局域网共享”，打开开关后记得看一下端口和授权设置。你可以设置一个访问密码，避免别人蹭你的代理。这个功能和 Clash Verge Rev 桌面端的“允许局域网连接”是一回事，只不过跑在了手机上。如果你同时用手机和电脑，建议把电脑端的局域网共享也打开，这样手机没电的时候电脑也能继续当网关。桌面端的操作可以参考 TUN 模式配置 里的相关说明。

一个实际场景：我出差的时候带着一台 iPad（只有 WiFi 版）和一台安卓手机。酒店 WiFi 没翻墙，我就用手机开 FlClash，iPad 的代理设置指向手机 IP，直接就能访问 Google Docs。整个过程不用任何额外的硬件。

🔔 通知栏与桌面小组件的快捷操作

FlClash 的通知栏快捷方式和桌面小组件做得相当用心，但很多人在安装后直接关掉了通知权限，完全没体验过。实际上，展开通知栏的下拉菜单里，你可以直接看到当前节点、连接状态，并且可以一键切换代理模式、切换节点、测试延迟。在通知栏点击“切换”按钮，它会弹出一个小型的节点选择器，完全不用打开 App。

桌面小组件则是另一个玩法。FlClash 提供了几种尺寸的小组件，最小的 1x1 小组件就是一个开关按钮，点击一下就切换 TUN 模式；更大的 2x2 小组件还能显示当前节点名称和网速。对于把手机当主力代理设备的用户，在桌面放一个小组件，出门看一眼就知道有没有掉线。

还有一个藏在设置里的“快速启动”功能：你可以给特定节点或配置创建桌面快捷方式，直接点击就切换过去。长按桌面 → 添加 FlClash 快捷方式，就能找到这个入口。这个功能在别的客户端里几乎没见过。

💾 备份与恢复：换机不折腾

换手机时最怕的就是代理配置全部要重来。FlClash 内置了一个比较完善的备份功能，在“设置” → “备份与恢复”里，你可以导出一个 ZIP 包，里面包含了所有配置文件、规则集、日志、以及应用的设置项。换新手机后，把这个 ZIP 包导入 FlClash，一切恢复原样。

不过有个小坑：备份文件里包含了你的订阅链接和节点信息，如果这个 ZIP 包被别人拿到，就等于把你的代理资源全部暴露了。所以备份文件一定不要上传到公共网盘，最好放在加密的私有存储里。如果你有多设备同步的需求，除了用 FlClash 的备份，还可以结合 Git 同步方案，把配置文件本身放在私有仓库里管理，比 ZIP 备份更安全。

另外，FlClash 也支持手动导出单个配置文件为 .yaml 文件，这个功能用来和桌面端 Clash Verge Rev 互换配置非常方便。你在电脑上调好的规则，导出成 YAML，传到手机里导入 FlClash，两边体验保持统一。

⚡ UDP 转发的精细控制

UDP 转发的问题可能是移动端代理最容易忽视的一环。很多用户会发现，用 FlClash 的时候，微信语音通话、FaceTime、或者一些游戏会出现卡顿甚至连不上，但看网页、刷视频完全正常。这往往就是 UDP 转发没有正确配置。

FlClash 在“设置”里有一个“UDP 转发”的开关，默认是开启的。但真正关键的是你的节点本身是否支持 UDP。很多机场节点在配置文件里会默认把 udp: true 显式声明，有些则没有。如果你的节点不支持 UDP 转发，即使客户端开关打开也没用。这时候你可以在配置文件中手动添加 udp: true 到对应节点，或者切换到其他支持 UDP 的节点。

还有一个更细的选项：在 FlClash 的“高级设置”里，你可以选择 UDP 转发模式——原生 UDP 还是 UDP over TCP。原生 UDP 延迟低，但某些网络环境下会被防火墙或运营商 QoS 限制；UDP over TCP 更稳定，但延迟会高一些。如果你在移动数据下遇到 UDP 丢包严重的情况，不妨试试 UDP over TCP 模式。

关于 UDP 的更多配置细节，可以结合 TUN 模式 中的 udp 相关参数来理解，FlClash 的底层也是走的同一套逻辑。

📊 URL 测试的隐藏参数与自动切换

FlClash 的“节点测试”功能看起来很直观：点一下测速按钮，所有节点开始跑延迟测试，然后按延迟排序。但大部分人不知道，测试的 URL 是可以自定义的。在“设置” → “URL 测试”里，你可以把默认的 http://www.gstatic.com/generate_204 改成任何你想要的地址。这对于某些特殊场景很有用：比如你只关心到某个特定服务器的延迟（比如 ChatGPT 的端点），就可以把测试 URL 改成 https://chat.openai.com/favicon.ico，这样 FlClash 在自动选择节点时就会优先选择到 ChatGPT 延迟最低的节点。

另外，策略组的“自动选择”模式（url-test）也有一个隐藏参数 tolerance，用来设置延迟容差值。默认情况下，只要某个节点延迟比当前节点低，就会切换过去。但这样可能造成频繁切换。如果在配置文件的策略组里加上 tolerance: 50，意思是只有当新节点比当前节点快 50ms 以上时才切换，大大减少了无谓的节点切换。这个参数在 FlClash 的图形界面里没有直接入口，需要手动编辑配置文件。你可以在 配置教程 里找到 url-test 策略组的完整参数说明。

⚠️ 注意： 如果测试 URL 填的是 https://chat.openai.com，而你的当前配置无法访问 ChatGPT（比如节点被 OpenAI 屏蔽），那么测试结果会显示超时，自动选择策略组会排除这些节点。这其实是个好消息，说明它真的在帮你筛选可用节点。

✍️ 写在最后

FlClash 的魅力不在于它有多少花哨的功能，而在于这些功能都藏在合适的位置，在你需要的时候刚好能找到。很多用户只是把它当作一个“点开就能翻墙”的工具，但如果花点时间把这些隐藏设置摸透，你会发现它完全可以当做一个完善的网络管理平台来用。

如果你是从其他客户端迁移过来的，建议先把 导入订阅 这篇看一遍，然后慢慢熟悉 FlClash 的配置结构。遇到问题的时候，常见问题 页面里已经整理了大量移动端场景的解决方案。当然，FlClash 作为一个活跃的开源项目，它的 GitHub 仓库和 Issue 讨论区也是很好的学习资源，项目地址你可以在 这里 找到。
